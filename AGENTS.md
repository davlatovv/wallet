# Repository Guidelines

## Project Structure & Module Organization

This repository is a Python 3.10+ personal-finance Telegram Mini App. User-facing functionality lives in `webapp/` (React + TypeScript + Vite), talking to a FastAPI backend in `app/presentation/api/`. The bot itself (`app/presentation/telegram/`) now only sends `/start` (with a button opening the Mini App) and payment-reminder notifications — the chat-based FSM flows were removed once the webapp covered the same ground (see `docs/MINIAPP_PLAN.md`, Phase 5). `main.py` is the bot's entry point and starts migrations, aiogram polling, and APScheduler. Core code lives in `app/` and follows a layered flow: `domain/` for dataclass entities, value objects, exceptions, and abstract repositories; `application/` for DTOs, interfaces, and use cases; `infrastructure/` for SQLAlchemy models, repository implementations, database sessions, exports, currency clients, and notifications; `presentation/api/` for FastAPI routers, schemas, and auth; `presentation/telegram/` for the bot's handlers, keyboards, middlewares, and router wiring. Alembic configuration is in `alembic.ini`, with migrations in `db/migrations/versions/`. Runtime exports are written under `exports/`.

## Build, Test, and Development Commands

- `python -m venv .venv && source .venv/bin/activate`: create and activate a local virtual environment.
- `pip install -e ".[dev]"`: install the app plus pytest tooling from `pyproject.toml`.
- `docker-compose up --build`: run PostgreSQL and the bot together.
- `alembic upgrade head`: apply database migrations when running services manually (the API does not run migrations itself — run this, or start the bot once, before `uvicorn`).
- `python main.py`: start the bot locally; requires `.env` with `BOT_TOKEN` and `DATABASE_URL`.
- `uvicorn app.presentation.api.main:app --reload --port 8000`: start the API locally; additionally requires `JWT_SECRET` in `.env`.
- `cd webapp && npm install && npm run dev`: start the Mini App frontend (Vite, `:5173`); requires `webapp/.env` (`cp webapp/.env.example webapp/.env`).
- `pytest`: run the Python test suite. Use `pytest -x` to stop at the first failure.
- `cd webapp && npx tsc -b --noEmit && npx oxlint src`: type-check and lint the frontend.

## Coding Style & Naming Conventions

Use 4-space indentation, type hints, and async/await consistently. Keep layer dependencies one-way: domain must stay framework-free; application should not import ORM or aiogram types; presentation should call use cases through `Container`, not query the database directly. Name modules by feature in snake_case, for example `manage_budgets.py`, `add_expense.py`, and `excel_exporter.py`. Alembic migrations use the existing `NNNN_description.py` pattern.

## Testing Guidelines

Tests should use `pytest`, `pytest-asyncio`, and `pytest-mock` from the dev dependencies. Place tests in a top-level `tests/` package mirroring the source area being covered. Prefer focused unit tests for domain value objects and use cases, and mock repositories or external services such as Telegram, CBU currency requests, and schedulers. Name files `test_<feature>.py` and test functions `test_<expected_behavior>`.

## Commit & Pull Request Guidelines

Recent history uses short imperative commit subjects, for example `Add debt selection logic...` and `Update deploy workflow...`. Keep commits focused. Pull requests should include a concise summary, migration notes when schema changes are present, local test results, linked issues if applicable, and screenshots or Telegram interaction notes for presentation changes.

## CI/CD Deployment

GitHub Actions runs on pushes and pull requests to `master`. The `lint` job checks Python syntax with `py_compile`. On push to `master`, the `deploy` job connects to the VPS via SSH, pulls the latest code in `/home/wallet`, restores the existing `.env`, and runs `docker compose up -d --build --remove-orphans`. Required repository secrets are `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`, and `VPS_PORT`.

## Security & Configuration Tips

Do not commit `.env` or secrets. Required local settings include `BOT_TOKEN` and asyncpg-style `DATABASE_URL` (bot), plus `JWT_SECRET` (API — `create_app()` refuses to start without it). Optional: `LOG_LEVEL`, `TIMEZONE`, `DEBUG`, `CORS_ORIGINS`, `WEBAPP_URL`, `JWT_TTL_MINUTES`, `RATE_LIMIT_REQUESTS`/`RATE_LIMIT_WINDOW_SECONDS`. Review autogenerated migrations before applying them, especially changes to money fields stored as UZS `Decimal` values.
